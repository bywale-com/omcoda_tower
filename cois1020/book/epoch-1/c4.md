## 4.1 Integral vs floating

**Integral types** store whole numbers. Memorize the nine:

`byte`, `sbyte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `char`

(`char` is on this integral list on the slide. You use it as a character in C8. `object` is on Table 2-1 even though you will not construct objects in this folder.)

**Floating-point** numbers contain decimal positions:

| Type | Slide claim |
|---|---|
| `float` | Up to seven significant digits |
| `double` | Default. 15 or 16 significant digits |
| `decimal` | More precision, smaller range. Money. |

### Table 2-1 — the columns, not only the names

The PDF’s type table is **system type, bytes, signed/unsigned, largest, smallest**, plus `string` and `object`.

Close this chapter and `EXAM-SURFACE.md`. In notes, reproduce Table 2-1. At minimum every **type**, **system type**, **bytes**, and **signed vs unsigned** for the integer rows. Exact min/max for `byte`, `sbyte`, `short`, `ushort`, `int`, `uint`. Approximate scientific ranges for `long` / `float` / `double` / `decimal` as the slide writes them. `char` 0xFFFF / 0x0000. `bool` / `string` / `object` NA where the table says NA.

This is MEMORIZE. Naming `int` and `double` is not covering the slide.

**FOUNDATION — why the table has size and signed at all (not extra exam facts beyond the table):**

A **bit** is a 1 or 0. A **byte** is 8 bits. Table 2-1’s **Bytes** column is “how much room.” **Signed** types use some of that room for negative; **unsigned** do not, so the same size reaches a higher positive (byte 0–255 vs sbyte −128–127). Different numeric types exist because **range, precision, and operations** differ — money (`decimal`) is not a 32-bit count (`int`). The table is not a vocabulary list; it is why `float val = 54.7;` is the wrong *kind* of literal.

## 4.2 Suffixes — feel the compiler

Predict, then paste each line into a throwaway method (or comment them one at a time):

```csharp
float val = 54.7;     // the slide says incorrect
```

## 4.4 Nine format characters, then the demo

The PDF: format specifiers “can be one of **nine** built-in format characters.” Form `X0` — X is the specifier, 0 is the precision.

**Table 2-2** (memorize **all nine**, not only the demo):

| Character | Description |
|---|---|
| `C`/`c` | Currency |
| `D`/`d` | Decimal |
| `E`/`e` | Scientific (exponential) |
| `F`/`f` | Fixed-point |
| `G`/`g` | General (decimal **or** scientific) |
| `N`/`n` | Number (with group separators) |
| `P`/`p` | Percent |
| `R`/`r` | Round trip (same value when converted back) |
| `X`/`x` | Hexadecimal |

The **running demo** on the next slide uses a subset (`{0}`, `F`, `F1`, `F3`, `E`, `C`, `C3`) on `34.456` then `23456.78`. Build that demo. Predict `F1` of `34.456` before you run. Write the seven lines.

Then, chapter closed, recite Table 2-2 including `D`, `G`, `N`, `P`, `R`, `X`. Construction of F/E/C is not coverage of the table.
