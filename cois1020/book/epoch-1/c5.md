## 5.1 Binary and unary

**Binary** operators take two **operands**: `z = x + y`.  
**Unary** take one: `z = -x`.

**FOUNDATION:** an **operator** is the symbol that names the operation. An **expression** (`x + y`) **evaluates** to a value. A **statement** (`z = x + y;`) is the instruction that uses that value. **Precedence** (EXAM below) is the rule for which operator in an expression runs first.

```csharp
int x = 8, y = 9, z;
z = x + y; // predict
z = -x;    // predict
```

Also use `*`, `/`, `%` (remainder) on small integers you chose.

**Table 2-3** (the slide’s own examples — predict, then run, then memorize):

| Expression | Slide result |
|---|---|
| 45 + 2 | 47 |
| 45 − 2 | 43 |
| 45 * 2 | 90 |
| 45 / 2 | **22 (not 22.5)** |
| 45 % 2 | 1 |

Integer `/` truncates. That fact is **on this table**. Why a `double` still shows `1.0` for `7 / 4` is C6.

## 5.2 Precedence

`*`, `/`, `%` bind tighter than `+`, `-`. Parentheses override.

```csharp

```

## 5.3 Shortcuts

`total = total + val` is `total += val`. Also `-=`, `*=`, `/=`.

The PDF introduces **prefix** and **postfix** increment as two writings of the same assignment:

```text
someValue = someValue + 1;
++someValue;    // prefix
someValue++;    // postfix
```

Decrement: `--`.

That is the whole claim. Do **not** print `n++` vs `++n` to study “old value vs new value.” That distinction is not on the slide. Illegal under source purity even though it is true C#.

In the program, increment a variable with prefix, then (a separate statement) with postfix. Show the value **after** each increment. Both should have added one. That matches the PDF.
