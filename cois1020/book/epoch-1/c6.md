# C6 — Conversion

`7 / 4` is why types are not decoration. This chapter is implicit vs explicit conversion.

Build in `constructions/c6/`.

Do not start `bool` / `string` methods.

---

## Leftover

If you printed `double result = 7 / 4;` you likely got `1.0`. In notes: did the `double` on the left fail, or did something happen **before** the assignment?

---

## 6.1 Same type keeps the type

Arithmetic on two `int`s produces an `int`. `7 / 4` in integers is `1`. Assigning that `1` to a `double` makes `1.0` — the fraction was already gone.

Predict both, then run:

```csharp
double truncated = 7 / 4;
double fraction = 7 / (double)4;
```

The second is an **explicit cast**: the type you want in parentheses, then the value.

---

## 6.2 Implicit widening

When types mix, C# picks a **unifying type** (higher precedence) and **implicitly** converts the other operand.

The slide: integrals can widen toward larger integrals and floating types (`int` → `long`, `float`, `double`, `decimal`). Among floating types, `float` automatically converts to `double`.

Show one implicit conversion you did not write a cast for:

```csharp
int whole = 5;
double widened = whole; // allowed
```

Predict whether `int narrowed = 5.9;` compiles. Try it. Restore. That direction is **not** implicit.

---

## 6.3 Words

- **Implicit cast** — automatic, to a higher-precedence type.
- **Explicit cast** — you write `(type)`.

You are not required to memorize a full numeric tower beyond what the slide said. You **are** required to predict `7 / 4` in a `double`.
