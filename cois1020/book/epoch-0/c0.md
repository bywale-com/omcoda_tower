## 0.1 Cause the chain

Create `cois1020/constructions/c0/Program.cs`.

Type this shape (put **your** name in the string):

```csharp
public static class Lab1
{
    public static void Main()
    {
        System.Console.WriteLine("Hello COIS1020H, my name is xxx");
        System.Console.ReadLine();
    }
}
```

Compile and run in Visual Studio (console application). Look at what you get.

Then, still before reading further, write in notes:

- What exists now that did not exist before you authored the file?
- What did you author, exactly?
- What did the machine do with it?
- Why did a window appear, and why did it wait?

### After you have written that

A **computer program** is a set of instructions that tells a computer what to do. Another word: **software**.

The file you typed is **source**. What ran is not the source; it is what compiling produced.

`Main` is the method a **console application** must have. `WriteLine` produced a line of output. The text in quotes is a **literal string** — an **argument** to the method.

`ReadLine` here is not “input class.” On Windows it holds the window so you can read the line. Leave it.

### Syntax you must produce without this chapter

- A file ending in `.cs`
- `public static class` *SomeName*
- `public static void Main()`
- `{` body `}`
- `System.Console.WriteLine("…");`
- `System.Console.ReadLine();`

Create a **second** file in the same folder (`once.cs` or a second project), print a different sentence, run it, then you may delete it. If you cannot do that with this chapter closed, stay here.

## 0.2 Face an error

The slides say: first program, **face errors**.

In notes, predict: if you delete the semicolon after `WriteLine(...)`, what happens when you compile — a running program with a missing character, or a refusal to run?

Do it. Write whether you were right. Restore the semicolon.

That refusal is a **syntax** problem. You do not need the word “debugging” yet. You needed a character the language requires.
