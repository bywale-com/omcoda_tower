## Why that mattered, and what changed the reading

The first reading was that the get must be claim 23’s pair, because the table’s key is the pair and the send had just been required to use it. The route’s missing firm would then be a hole: find the firm the caller is acting as, and put it in the predicate. That reading needs a caller who is acting as a firm.

The callers do not supply one. The port’s `get` was typed without a firm, while `setConsent` and `silence` take one. The real adapter follows that type. The handler does not turn the session cookie into a firm. The only screen that calls `get` passes a demo contact id and reads a boolean into a register prototype. The firm constant on that scene is used by the writes and is absent from the get. The product face already has the pair on the seat, and claim 23 already has the pair on the send. Those are the reads that apply a firm’s consent. This route is the port’s contact-id get. Treating it as the pair would add a firm the call does not have.

The second reading was that `firm-cedar` is implicit, because the scene that calls `get` writes with that id. That would pin an open route to a demo constant the request does not carry. A get for any other contact id would return Cedar’s row only. The scene is not the product face, and it is not an operator session acting as Cedar. The ant contact scene and the product-face workspace, which are the other contact paints, do not call this route at all.

The third reading was the session cookie. `wireFetch` always sends it, and `requireSessionFirm` is how machine and send handlers learn the firm. This handler is not among them. Using the cookie would make a logged-in firm the answer for `sarah`, or would 401 when there is no session. The route today returns the defaults with no session. The prototype is not presenting the demo id as that session’s contact.

What remained is the query as written. One row for the contact id, or the defaults. When two firms have a row, `LIMIT 1` with no `ORDER BY` does not define which. That indeterminacy is the return. It can change the boolean the register prototype paints for `sarah`. It does not change the send, the seat, or the operator bind screen, because those do not read this route.
