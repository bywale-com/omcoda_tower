# How trees — index

**Outcomes:** [`../OUTCOMES.md`](../OUTCOMES.md)  
**Method:** omcoda-hq `register-manual` Function chapter · Tower `docs/build-foundation/01-ui-first-and-how.md` · leaf click-path (`Starting from {Module}` / `On {Surface}`) · taxonomy Module → Modal → Block → Submodal.

## Laws for this pass (do not violate)

1. **Subjects only:** Consultant · Engagement contact · Operator. Never "As Tower" / "As House."
2. **Engagement machinery is not an outcome.** Opt-in / nudge / reactivation / refresh / re-evaluate appear only as **requirements** at leaves — usually attributed to **operator-side** modules.
3. **Consultant core stays short.** Hand-over · authorize · receive. Its How-tree **hands most leaves across** to operator surfaces. Do **not** "fix" that by pulling Automations / Agents / evaluation authorship back under the consultant desk.
4. **Hub placement is a revision, not destination.** Audits / Agents / Automations live in the firm shell today; personas + this lattice put authorship on the Operator. Leaves name the **operator Module** as the rightful home and mark today's Hub parking as **existing-wrong-seat** when relevant.
5. **Leaf click-path:** most-relative container; invent Title Case Module/Modal/Block names when nothing fits; mark **existing** vs **new**.
6. **Affordance grain:** Clarity names controls and, for state-writing affordances, the downstream reader. Components: `UI · Kind · Status · Affordance`. See [`../sme/implementation/CLICKPATH-DENSIFICATION.md`](../sme/implementation/CLICKPATH-DENSIFICATION.md).
7. **Person vs view-only vs external:** Person acting → click-path language (`click` / `select` / …). View-only of backend → `view`. Past app edge → intent only (no invented external UI). Never “ops runs…”.
8. **Writing only.** No CT plant. Preference + requirements — not a doability verdict.

## Format per tree file

- Outcome statement (verbatim from OUTCOMES.md)
- Root → answer nodes (DNA cuts) → leaves
- Each leaf: Question · Clarity (click-path) · Criteria · UI kinds · Existing/new · Requirements (build side)
