## How to read a plate

Every mark on a canon image is one of three things:

| Kind | What it is | What you do |
|------|------------|-------------|
| **Spec** | A real control, node kind, or persistable grain | Build / ascribe |
| **Example name** | A name we used so the picture had something in it. Operator can rename. Templates *may* be seeded because we already know what belongs inside — easy to mess up if you freeze the name as a type | Seed optional. Do not freeze the string as a table token |
| **Founder caption** | Written so the founder could read the picture. Not a node. Not a picker. Not a query. Not `qualify_gate` | Obey the **idea** if it is already law. Do not put the sentence into the system |

A green tick / “objective met” on the wire between campaigns is allowed as chrome. It is still **not** a node and **not** a reason to invent a gate.

## The C3 correction (the one that triggered this)

Plate: [`C3-two-campaigns.png`](./agents-blueprint/C3-two-campaigns.png).

**There is no “first objective.”** There is an **objective**. A campaign has one. You string as many campaigns as you want **when that objective is met**.

**Launch window** and **Launch day** are **campaign names we used as an example** of multiple campaigns on one sequence. One of the first images. The operator can rename both. They are not system types.

**“They opt in”** on campaign 2 is a **title at best**. It is not an objective class.

**“qualify — first objective met”** on the wire is a **founder caption of the distance** between two campaigns. It communicates the system fact: the previous campaign’s objective was met. It is **not** a qualify node. It is **not** a third radio. It is **not** `qualify_gate`. A tick on that distance is fine. It must not cause a systems question unless the question is something else (it was not).

The 17:05 waitlist-vs-whole-book fork is **not** on this plate. Do not hide a waitlist filter behind that caption.

## What this does to the 17:05 / `qualify_gate` question

It **closes** it as a UI question. There is no qualify control. There is no “first objective.”

System: when a campaign’s **objective is met**, the next campaign you strung can run. That is already the objective. Do not invent `qualify_gate` from the C3 pill.

Waitlist vs whole book is **not on C3**. If someone still needs that product rule, it is a **new** ask, not a reading of this picture.

C2 Additional stays disabled. Attempt numbers may live on the campaign without chrome on C3–C5. Those were already specified.

## What you may seed (and how to mess it up)

You **may** create sequence templates (opt-in / re-engagement / reactivation) and campaign templates (the two-campaign teaching opt-in) because we already said what belongs inside.

You mess it up if you:

- Freeze those **names** as CHECK tokens or as “the” two campaigns every sequence must have
- Turn “qualify” into a node or a gate column
- Treat “first objective” as a field
- Treat “they opt in” as an objective class
- Build A10 / A13 as a page
- Put founder captions into Postgres
